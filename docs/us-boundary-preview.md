# 미국 경계 미리보기

`/demo/?country=US`에서 편집 창을 열고 왼쪽 **카운티 경계**를 누르면 뉴욕 카운티 경계를 표시합니다. 기존 **경계 > 경계 종류** 메뉴 상단의 **국가**에서 대한민국·미국을 검색하고 변경할 수 있습니다. 주·특별구·영토, 카운티, 카운티 하위구역, 도시·타운, 우편번호 통계구역(ZCTA)을 선택할 수 있습니다. 뉴욕·샌프란시스코·미국 본토 버튼으로 이동하거나 지도를 움직인 뒤 **현재 화면 불러오기**로 갱신합니다. 미국 본토 버튼은 주 경계를 선택합니다.

미국 경계는 별도의 참고 레이어입니다. Google 로그인 없이 조회하며, 편집 scene·선택·undo/redo·완료 결과에 추가하지 않습니다. 한국 경계의 로그인·국가 제한·Supabase 조회 경로는 기존 정책을 유지합니다.

## 국가 선택과 URL

- `/editor/?country=US` 또는 `/demo/?country=US`로 초기 국가를 지정합니다. `KR`은 대한민국이며, 생략하거나 지원하지 않는 값이면 `KR`을 사용합니다. 대소문자는 구분하지 않습니다.
- 메뉴에서 국가를 바꾸면 현재 편집 창의 URL도 갱신합니다. IP 국가 추정이나 자동 리디렉션은 사용하지 않습니다.
- 국가 목록은 한국어·영문 이름·국가 코드로 검색하고 키보드로 선택할 수 있습니다. 현재 데이터가 연결된 한국과 미국만 표시하며, 공통 카탈로그는 `src/shared/config/boundaryCountries.ts`에 있습니다. 다른 국가를 추가할 때는 해당 국가의 조회 기능과 경계 종류도 연결해야 합니다.
- 한국 경계는 실제 조회를 선택할 때 Google 로그인을 요청합니다. 국가 메뉴 탐색과 미국 참고 경계 조회에는 로그인이 필요하지 않습니다.
- 국가별 마지막 지도 위치를 편집 회차 안에서 복원하며, 국가 변경은 편집 도형·선택·실행 취소 이력에 영향을 주지 않습니다. 메뉴를 닫아도 경계 도구가 활성 상태면 참고 경계는 유지됩니다.

## 데이터와 보존

- U.S. Census Bureau의 2026 TIGER/Line, 5종 106,176개 경계를 사용합니다. ZCTA는 2020 Census 기준 통계구역이며 실제 USPS 배송구역과 다릅니다.
- WGS84 원본에서 GEOS 위상 보존 단순화를 수행한 단일 표시본을 모든 줌에 사용합니다. 허용 오차는 `0.00008`도이며 소수점 반올림은 하지 않았습니다.
- 원본은 별도 R2 접두어에 보존합니다. 개별 피처의 ID·속성·폴리곤·내부 링 수는 유지합니다. 인접 피처 간 공유 경계 일치까지 보장하는 방식은 아닙니다.
- 원본 기준계 변환의 태평양 영토 근사 처리 등 위치 정확도 한계는 배포 manifest에 기록합니다.
- 원본이나 표시용 경계 파일은 GitHub와 `public/`에 넣지 않습니다. 이 저장소에는 조회 코드·고정 버전 참조·합성 테스트 도형만 있습니다.

## R2 연결

`wrangler.toml`의 `US_BOUNDARIES` 바인딩은 `maps-editor-boundaries` 버킷을 가리킵니다. Cloudflare Pages에 배포하면 Functions가 이 바인딩을 사용합니다. 버킷 자체의 공개 접근을 활성화할 필요는 없습니다.

현재 표시본 버전은 `src/shared/config/usBoundaries.ts`에서 고정합니다. 파일 구조는 다음과 같습니다.

```text
us/<display-version>/manifest.json
us/<display-version>/indexes/<kind>.json
us/<display-version>/z15-plus/<kind>/<part>.json
```

`GET /api/us-boundaries?version=<display-version>&file=<relative-key>`는 고정 버전의 manifest, 종류별 인덱스, 표시용 JSON만 읽습니다. 다른 버전·원본·경로 탐색·쓰기 메서드는 허용하지 않습니다. R2의 gzip 객체를 스트리밍으로 풀어 JSON을 캐시하고, 브라우저 전송 시 Cloudflare가 gzip/Brotli를 협상합니다. 이렇게 압축 중복을 방지하며, ETag·조건부 요청·버전별 브라우저/Cloudflare 캐시를 사용합니다. 배포용 비밀값이나 계정 토큰은 브라우저에 전달하지 않습니다.

일반 `npm run dev`는 Pages Functions를 실행하지 않습니다. 실제 R2 확인은 바인딩을 적용한 Pages 미리보기 배포에서 수행합니다. 자동 E2E는 이 경로의 HTTP 응답을 합성 데이터로 대체하므로 네트워크 자격 증명 없이 실행됩니다.

## 조회와 제한

종류별 bbox 인덱스로 현재 화면에 겹치는 피처의 파일만 선택합니다. 최대 4개 파일을 동시에 받고, 종류·국가 변경, 경계 숨기기 또는 다른 도구 전환 시 진행 중인 요청을 취소합니다. 같은 버전의 인덱스·파일은 TanStack Query 캐시로 재사용합니다.

한 화면에 2,000개 피처, gzip 파일 합계 20MiB, 표시할 꼭짓점 1,000,000개를 넘으면 확대 안내를 표시합니다. 조회 실패나 일부 누락은 완전한 결과로 표시하지 않습니다. 임의 viewport의 결과를 원본이나 편집용 폴리곤으로 저장하지 않습니다.

## 검증

단위 테스트는 객체 경로·버전 제한, gzip/캐시 응답, viewport 파일 선택, 과다 조회, 누락·실패·취소 및 재사용을 확인합니다. E2E는 실제 canvas 경계 픽셀, 기존 편집 상태 불변, 종류 전환·숨기기·재시도·빈 결과, URL 전달·국가 검색·키보드 선택·국가 전환·좁은 화면 배치를 확인합니다.
