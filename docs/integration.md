# 연동 인터페이스

**서비스 페이지에서 편집 창을 열고, 편집 데이터를 보내고, 편집 결과를 받는 방법을 설명합니다.** 관리자 화면이나 입력 폼에서도 연결할 수 있으며, 서비스 페이지에 지도가 있어야 하는 것은 아닙니다. 서비스 페이지에 자바스크립트 코드를 추가할 수 있으면 됩니다.

이 문서에서 **서비스 페이지**는 편집 창을 열고 데이터를 주고받는 웹페이지, **편집 창**은 전달받은 도형을 편집하는 Termia 창입니다. **편집 데이터** (`scene`)에는 도형 목록과 관련 설정이 들어갑니다. 코드에 쓰인 식별자는 그대로 두고, 설명에서는 이 용어를 사용합니다.

일반 연동에는 Termia 저장소 복제, 내부 코드 수정, 참고 경계 서버나 로그인 설정이 필요하지 않습니다. 편집기를 직접 운영할 때도 같은 인터페이스를 사용하며, 운영 설정은 [직접 운영·커스텀](self-hosting.md)을 참고하세요. 실행 가능한 웹 문서는 [연동 인터페이스](https://maps-editor.pages.dev/integration/)에서 볼 수 있습니다.

## 편집기 주소와 연결 조건

편집기 주소: `https://maps-editor.pages.dev/editor/`

| 조건                      | 설명                                                                                                                      |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| HTTPS 서비스 페이지       | 편집기와 도메인이 달라도 연결할 수 있습니다. 기본 설정에서는 별도 도메인 등록이 필요하지 않습니다.                        |
| HTTP·localhost            | 편집기와 사이트 주소(`origin`)가 같거나, 편집기 운영자가 서비스 페이지의 사이트 주소를 별도로 허용해야 합니다.            |
| 연결 사이트를 제한한 배포 | HTTPS라도 편집기 운영자가 설정한 허용 목록을 따릅니다.                                                                    |
| 새 창 연결                | 사용자의 클릭으로 새 창을 열고, 결과를 받을 때까지 서비스 페이지를 열어 두어야 합니다. `window.opener` 연결을 유지합니다. |

**사이트 주소** (`origin`)는 프로토콜·도메인·포트의 조합이며 경로는 제외합니다. `https://service.example.com/orders/1`의 사이트 주소는 `https://service.example.com`입니다. `http://localhost:3000`에서 공개 편집기를 사용하려면 별도 허용이 필요하고, 서비스 페이지와 편집기를 모두 같은 로컬 주소에서 실행하면 기본 설정으로 연결됩니다.

`noopener`·`noreferrer` 또는 창 연결을 끊는 보안 정책을 사용하면 이 흐름으로 연결할 수 없습니다. `file://`와 `null` origin은 지원하지 않으며, iframe은 이 새 창 인터페이스의 지원 대상이 아닙니다.

주소만 여는 것으로는 편집 데이터가 전달되지 않습니다. `/editor/`를 직접 열면 서비스 페이지의 데이터를 기다립니다. 편집 창이 서비스 페이지나 서비스 서버에서 데이터를 자동으로 읽는 것은 아닙니다.

### 초기 경계 국가 지정

`/editor/?country=US`로 열면 경계 메뉴의 초기 국가가 미국, `/editor/?country=KR`이면 대한민국입니다. 생략하거나 지원하지 않는 값이면 대한민국을 사용합니다. 데모의 `/demo/?country=US`도 편집 창에 같은 설정을 전달합니다.

사용자는 **경계 > 국가**에서 다른 국가를 선택할 수 있고, 선택한 값은 현재 편집 창 URL에 반영됩니다. 이 값은 경계 메뉴의 초기 설정이며 편집 데이터나 접근 권한을 바꾸지 않습니다. IP로 국가를 자동 결정하지 않습니다. 한국 경계는 기존 Google 로그인 정책을 따르고, 미국 경계는 [R2의 표시용 참고 데이터](us-boundary-preview.md)를 사용합니다.

## 두 창 사이의 메시지 흐름

두 창은 브라우저의 `postMessage` 기능으로 데이터를 주고받습니다.

1. 서비스 페이지에서 메시지를 받을 함수를 등록한 뒤, 사용자 클릭으로 편집 창을 엽니다.
2. 편집 창의 **준비 완료 알림** (`MAP_EDITOR_READY`)을 받습니다.
3. 서비스 페이지가 **편집 시작 데이터** (`MAP_EDITOR_INIT`)를 보냅니다. 이번 편집을 구분하는 **편집 작업 ID** (`sessionId`)와 **편집 데이터** (`scene`)를 넣습니다.
4. 사용자가 편집을 완료하면 서비스 페이지가 **편집 결과** (`MAP_EDITOR_SUBMIT`)를 받습니다. 취소하면 **편집 취소 알림** (`MAP_EDITOR_CANCEL`)만 받습니다.
5. 서비스 페이지가 메시지를 검증하고 편집 창을 닫은 뒤 결과를 반영합니다. 서버에 저장할 필요가 있으면 서비스의 저장 기능을 호출합니다.

| 메시지 `type`       | 방향                    | 의미·데이터                                                       |
| ------------------- | ----------------------- | ----------------------------------------------------------------- |
| `MAP_EDITOR_READY`  | 편집 창 → 서비스 페이지 | 준비 완료 알림. 편집 데이터 없음                                  |
| `MAP_EDITOR_INIT`   | 서비스 페이지 → 편집 창 | 편집 시작. `sessionId`, `scene`                                   |
| `MAP_EDITOR_SUBMIT` | 편집 창 → 서비스 페이지 | 편집 결과. 동일한 `sessionId`, 전체 `scene`                       |
| `MAP_EDITOR_CANCEL` | 편집 창 → 서비스 페이지 | 편집 취소. 동일한 `sessionId`, `scene` 없음                       |
| `MAP_EDITOR_ERROR`  | 편집 창 → 서비스 페이지 | 오류 알림. `message`, 선택적 `issues`; `sessionId`가 없을 수 있음 |

`sessionId`는 서비스 페이지가 편집 작업마다 만드는 비어 있지 않은 고유 문자열입니다. 로그인 정보가 아닙니다. 같은 편집 창이 준비 완료 알림을 다시 보내면, 같은 편집 작업 ID와 처음 보낸 편집 데이터로 응답합니다.

새 `MAP_EDITOR_INIT`는 편집 내용과 이력을 초기화합니다. 편집 중 데이터를 갱신하는 용도로 보내지 마세요. 중간 변경 알림이나 자동 저장 메시지는 제공하지 않습니다.

## 최소 예제: 사각형 하나 보내고 결과 JSON 받기

지도 라이브러리 없이 버튼과 결과 표시 영역만으로 연동할 수 있습니다. [웹 최소 코드 예제](https://maps-editor.pages.dev/integration/#example)에서도 아래 연결 코드를 확인할 수 있습니다. 바로 편집해 보려면 [경복궁 실습](https://maps-editor.pages.dev/integration/#quickstart)을 이용하세요.

서비스 프로젝트에서 `npm install zod`를 실행하고 다음 세 파일을 같은 폴더에 복사합니다. TypeScript를 빌드하는 웹 프로젝트를 기준으로 합니다.

| 파일                                                                                        | 역할                                           |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| [minimal-service.example.ts](../src/pages/docs/content/examples/minimal-service.example.ts) | 사각형 하나를 보내고 편집 결과를 JSON으로 표시 |
| [map-editor-host.example.ts](../src/pages/docs/content/examples/map-editor-host.example.ts) | 편집 창 열기·메시지 검증·창 닫기               |
| [editor-contract.example.ts](../src/pages/docs/content/examples/editor-contract.example.ts) | 편집 데이터 타입과 결과 메시지 검증            |

`createMapEditorHost`는 복사해서 사용하는 연결 코드이며 별도로 배포된 SDK가 아닙니다. 이름에 있는 `Host`는 서비스 페이지의 역할을 뜻합니다.

서비스 페이지에 버튼과 결과 표시 영역을 만듭니다.

```html
<button id="edit-shape" type="button">도형 편집하기</button>
<pre id="edit-result" aria-live="polite"></pre>
```

두 요소가 만들어진 뒤 서비스 페이지의 코드에서 연결합니다.

```ts
import { mountMinimalExample } from "./minimal-service.example";

const button = document.querySelector<HTMLButtonElement>("#edit-shape");
const result = document.querySelector<HTMLPreElement>("#edit-result");

if (!button || !result) throw new Error("편집 버튼과 결과 영역이 필요합니다.");

const dispose = mountMinimalExample(
  button,
  result,
  "https://maps-editor.pages.dev/editor/",
);

// 페이지를 떠날 때 정리합니다. 뒤로가기로 복원할 페이지는 연결을 유지합니다.
window.addEventListener("pagehide", (event) => {
  if (!event.persisted) dispose();
});
// React 등에서는 서비스 페이지의 컴포넌트를 제거할 때도 dispose()를 호출합니다.
```

버튼을 누르고 편집 창에서 사각형의 정점을 옮긴 뒤 **‘저장하고 편집 완료’**를 누르세요. 이 버튼은 편집 결과를 서비스 페이지로 보냅니다. 결과 표시 영역에 전체 편집 데이터가 나타나며, 다시 편집하면 방금 받은 결과로 시작합니다. 예제는 서버에 저장하지 않으며 새로고침하면 최초 사각형으로 돌아갑니다.

자신의 서비스에 적용할 때는 예제의 사각형을 실제 편집 데이터로 바꾸고, 결과를 받는 `onSubmit` 함수에 화면 반영이나 서버 저장을 연결합니다.

## 편집 데이터 규격 (`scene`, 버전 2)

```json
{
  "version": 2,
  "features": [
    {
      "id": "area-1",
      "name": "배송구역 A",
      "geometry": {
        "type": "Polygon",
        "coordinates": [
          [
            [126.975, 37.576],
            [126.982, 37.576],
            [126.982, 37.5855],
            [126.975, 37.5855],
            [126.975, 37.576]
          ]
        ]
      },
      "properties": { "serviceAreaId": "delivery-001" }
    }
  ]
}
```

| 필드                    | 문서 용어             | 필수 여부·의미                                                      |
| ----------------------- | --------------------- | ------------------------------------------------------------------- |
| `version`               | 데이터 형식 버전      | 필수. 현재 `2`                                                      |
| `features`              | 도형 목록             | 필수. 빈 배열 `[]`로 새 도형부터 시작할 수도 있음                   |
| `features[].geometry`   | 도형의 형태와 좌표    | 필수. GeoJSON geometry 형식                                         |
| `features[].id`         | 도형 ID               | 선택. 지정하면 도형마다 중복되지 않는 값 사용                       |
| `features[].name`       | 도형 이름             | 선택. 편집 창의 목록에 표시할 이름                                  |
| `features[].properties` | 추가 정보             | 선택. 배송구역 ID 등 서비스가 도형에 붙여 주고받는 정보             |
| `features[].locked`     | 잠금 상태             | 선택. 편집 화면에서 해제할 수 있는 잠금이며 서버의 권한 설정이 아님 |
| `features[].visible`    | 표시 상태             | 선택. 숨긴 도형도 편집 결과에 포함                                  |
| `features[].themeToken` | 도형 색상 설정        | 선택. 편집기가 사용하는 테마 값                                     |
| `id`, `name`            | 편집 데이터의 ID·이름 | 선택. 개별 도형의 ID·이름과 구분                                    |
| `viewport`              | 지도 위치 설정        | 선택. 현재 입출력에 보존되지만 화면의 시작 위치에는 적용되지 않음   |

좌표는 WGS84의 **`[경도, 위도]`** 순서입니다. 경도는 -180~180, 위도는 -90~90 범위여야 합니다. 다른 좌표계를 사용하는 서비스는 보내기 전에 변환하고, 결과 반영 시 필요한 역변환을 처리합니다.

점(`Point`, `MultiPoint`), 선(`LineString`, `MultiLineString`), 다각형(`Polygon`, `MultiPolygon`)을 지원합니다. 다각형에는 서로 다른 정점이 3개 이상 필요합니다. 예제처럼 첫 좌표와 마지막 좌표를 같게 하여 경계를 닫으세요. 열린 경계는 입력을 정리할 때 자동으로 닫습니다.

지도 인스턴스나 지도 라이브러리의 객체 대신 위 형식의 데이터를 보냅니다. GeoJSON `FeatureCollection` 자체도 이 인터페이스의 입력 형식은 아닙니다. 도형 목록의 뒤쪽 항목이 지도 위쪽에 표시됩니다.

도형은 전달한 좌표 위치에 표시됩니다. 현재 편집 창은 기본 중심 `[126.98, 37.57]`, 줌 12에서 시작하며 도형이 있는 범위로 자동 이동하지 않습니다.

## 편집 결과 받기·화면에 반영하기·서버에 저장하기

다음 세 동작을 구분합니다.

| 동작            | 담당·의미                                                     |
| --------------- | ------------------------------------------------------------- |
| **편집 완료**   | 편집 창이 `MAP_EDITOR_SUBMIT`으로 결과를 서비스 페이지에 보냄 |
| **결과 반영**   | 서비스 페이지의 데이터와 화면을 받은 결과로 갱신함            |
| **서버에 저장** | 서비스의 저장 기능으로 결과를 영구 보관함                     |

**편집 결과에는 변경한 도형뿐 아니라 전체 도형 목록이 들어갑니다.** 예를 들어 `area-1`의 정점 하나를 옮기면 같은 도형 ID와 추가 정보에 수정된 좌표가 담깁니다. 수정하지 않은 도형도 함께 반환됩니다. 받은 전체 편집 데이터를 서비스에 보관하면 다음 편집도 수정본으로 시작합니다.

| 편집 내용                        | 서비스 페이지가 받는 결과                                           |
| -------------------------------- | ------------------------------------------------------------------- |
| 정점 이동·합치기·빼기            | 수정된 형태와 좌표(`geometry`)                                      |
| 도형 삭제                        | 도형 목록(`features`)에서 해당 도형 제외                            |
| 도형 숨김·잠금                   | 도형은 포함하며 `visible`·`locked`에 상태 반영                      |
| 직접 그리기·참고 경계 추가       | 새 도형 ID가 있는 도형 포함. 서비스 업무 ID는 서비스에서 연결       |
| 행정동·법정동을 참고로 보기만 함 | 참고 경계는 편집 결과에 포함하지 않음                               |
| 편집 취소                        | `MAP_EDITOR_CANCEL`만 수신. 편집 데이터가 없으므로 기존 데이터 유지 |

기존 도형의 추가 정보는 유지되지만 새로 만든 도형에 서비스 업무 ID가 자동으로 생기지는 않습니다. 편집기의 내부 레이어·선택 상태·편집 이력·인증 토큰도 결과에 포함하지 않습니다.

점이나 선만 있는 편집 데이터도 편집을 완료할 수 있습니다. ‘반환할 폴리곤이 없습니다’는 안내 문구이며 결과 전송을 막는 조건이 아닙니다.

서비스 서버에 영구 저장하려면 결과를 받은 뒤 저장 API를 호출하고, 저장 실패 안내와 재시도를 구현합니다. 편집 창의 **‘저장하고 편집 완료’는 서비스 서버의 저장 성공을 의미하지 않습니다.** 결과 메시지 검증과 별도로 서비스 서버에서 업무별 면적·위치·저장 권한을 검증해야 합니다.

## 여러 도형과 기존 지도에 연결하기

최소 연동을 확인했다면 [경복궁 실습](https://maps-editor.pages.dev/integration/#quickstart)에서 다각형·선·점을 함께 편집하고 지도와 결과 JSON을 갱신해 보세요. 실제 지적·행정 경계나 공식 관람 동선이 아닌 연습용 데이터입니다. [편집 도구 안내](https://maps-editor.pages.dev/editing/#screen)에서 도구 위치와 동작을 확인할 수 있습니다.

- [input-scene.example.ts](../src/pages/docs/content/examples/input-scene.example.ts): 다각형·선·점 입력. [주석 포함 JSONC](../src/pages/docs/content/examples/input-scene.example.jsonc)도 제공합니다.
- [gyeongbokgung.example.ts](../src/pages/docs/content/examples/gyeongbokgung.example.ts): `mountPalaceExample(button, resultElement, editorUrl)`로 실습 연결.
- [service-page.example.ts](../src/pages/docs/content/examples/service-page.example.ts): 기존 지도가 있는 서비스에서 결과를 GeoJSON으로 바꾸어 표시하는 연결 예제.

기존 지도 예제의 `bindMapEditor`는 다음 값들을 받습니다. 앞서 복사한 메시지 연결·검증 파일을 함께 사용합니다.

| 항목                             | 서비스 페이지에서 제공할 값                                          |
| -------------------------------- | -------------------------------------------------------------------- |
| `editorUrl`                      | 편집기 주소                                                          |
| `openButton`                     | 사용자가 누를 버튼                                                   |
| `getScene()`                     | 현재 편집 데이터를 반환하는 함수                                     |
| `applyScene(scene)`              | 받은 전체 편집 데이터를 서비스 상태에 반영하는 함수                  |
| `renderOnMap(featureCollection)` | 받은 도형을 사용하는 지도 라이브러리의 형식으로 바꾸어 표시하는 함수 |
| `showEditorError(message)`       | 오류를 안전하게 표시하는 함수                                        |

`applyScene`에서 `getScene`이 읽는 데이터를 갱신하면 다음 편집도 수정본으로 시작합니다. 연결 함수가 반환하는 정리 함수는 서비스 페이지의 컴포넌트를 제거할 때 호출합니다. 중복 클릭은 이미 열린 편집 창으로 이동하며, 취소하면 결과 반영 함수를 호출하지 않습니다.

## 메시지 검증과 문제 해결

연결 예제는 다음을 확인한 뒤 결과를 반영합니다.

- **메시지를 보낸 창** (`event.source`): 서비스 페이지가 연 편집 창인지 확인합니다.
- **사이트 주소** (`event.origin`): 설정한 편집기 주소의 origin과 정확히 같은지 확인합니다. 수신한 메시지에서 목적지를 추측하지 않습니다.
- **편집 작업 ID** (`sessionId`): 완료·취소 메시지가 현재 편집 작업의 것인지 확인합니다.
- **데이터 형식**: 편집 결과의 구조와 좌표가 인터페이스에 맞는지 검사합니다.

편집 데이터를 보내는 `postMessage`에는 정확한 사이트 주소를 `targetOrigin`으로 지정합니다. `"*"`를 사용하지 않습니다. 편집 창의 데이터 없는 최초 준비 완료 알림만 예외입니다.

| 증상                             | 확인할 내용                                                                                                                   |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 편집 창이 열리지 않음            | 사용자가 누른 버튼에서 `window.open`을 실행하는지, 브라우저가 팝업을 차단했는지 확인                                          |
| 편집 창이 데이터를 기다림        | 창을 열기 전에 메시지 수신 함수를 등록했는지, 준비 완료 알림에 시작 데이터를 보내는지, `window.opener` 연결을 유지했는지 확인 |
| HTTP·localhost에서 연결되지 않음 | 편집기와 같은 사이트 주소인지, 다르다면 편집기 운영자가 서비스 페이지 주소를 허용했는지 확인                                  |
| 시작 데이터 오류                 | 버전 `2`, 도형 목록, 좌표 순서·범위, 중복 도형 ID 확인                                                                        |
| 편집 결과가 반영되지 않음        | 메시지를 보낸 창·사이트 주소·편집 작업 ID·데이터 검증과 결과 반영 함수 확인                                                   |
| 참고 경계를 불러오지 못함        | 편집 창의 로그인 안내를 따르고, 접근 문제가 계속되면 편집기 운영자에게 문의                                                   |

오류 알림의 `message`는 외부 입력이므로 HTML로 실행하지 않고 문자열로 표시합니다. 서비스 페이지가 편집 창에 Google 토큰이나 경계 API 키를 보낼 필요는 없습니다.
