# 지원 범위와 후속 작업

현재 구현을 파악하기 위한 요약입니다. 과거의 단계별 계획은 Git 이력에 남기고, 미완료 업무의 실시간 상태는 [GitHub Issues](https://github.com/kimik-hyum/map-editor/issues)에서 관리합니다.

## 지원하는 흐름

- 부모 팝업 연동: READY → INIT → SUBMIT/CANCEL, source·origin·세션 및 입력 검증
- GeoJSON 6종 입력과 평탄한 도형 스택, 선택·잠금·표시·이름·순서 변경
- 선택·정점 편집·보조키 이동, 마우스·키보드 그리기, 반경 폴리곤
- 폴리곤 병합·차집합·교집합, 외부 경계 원본 채택
- 도형 편집 undo/redo와 진행 중 작업의 완료 차단
- 일반 편집 비로그인 허용, 경계 선택 시 Google 로그인과 인증된 함수 조회
- 공개 v2 결과 반환. 부모의 서버 저장은 별도 구현

## 지원을 약속하지 않는 범위

| 범위                    | 현재 경계                                                                      |
| ----------------------- | ------------------------------------------------------------------------------ |
| iframe 연동             | `window.opener` 기반 새 창을 사용하며 제3자 iframe 저장소 제약은 검증하지 않음 |
| 자동·중간 저장          | CHANGE 메시지나 부모 서버 쓰기를 제공하지 않음                                 |
| 업무별 geometry 유효성  | 자기교차·허용 면적·영업 영역 등 업무 규칙은 부모·서버에서 추가 검증            |
| 날짜변경선·극점 반경    | 지원하지 않는 결과를 명시적으로 거부                                           |
| 대량 scene 성능 보장    | 실제 도형·정점 규모별 성능 예산은 별도 측정 필요                               |
| 특정 도메인만 호출 보장 | Origin은 보조 검사. 사용자 JWT·서버 계정 정책이 실제 접근 경계                 |

## 다음 작업의 판단 기준

새로운 기능을 미리 확장하지 않고, 실제 요구가 발생한 범위의 이슈를 먼저 확정합니다. 주요 후속 주제는 geometry 업무 규칙, 대량 렌더링, 경계 적재·원천 버전 자동 검증, 연산 후 출처·메타데이터 정책입니다.

구현 위치는 [아키텍처](../src/pages/editor/ARCHITECTURE.md), 도구 계약은 [도구·상태 모델](editor-tool-model.md), 배포 점검은 [운영 점검](editor-open-questions-review.md)을 참고하세요.
