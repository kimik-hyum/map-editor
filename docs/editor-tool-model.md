# 에디터 도구·인터랙션 모델

정리일: 2026-05-31
갱신: 2026-07-17 — 폴리곤·패스·마커 Draw와 정점 로컬 history 구현 상태 반영.

좌측 도구(rail)와 하위 옵션, 선택/편집 인터랙션의 현재 합의·구현 상태를 코드 기준으로 정리한 참조 문서다.
설계 논의의 원본 메모는 이슈 #35이며, 이 문서는 거기서 결정된 모델을 구현 기준으로 다듬어 체크인한 스냅샷이다.

## 1. 도구 (rail)

좌측 rail은 4개의 도구를 세로로 둔다. 활성 도구(`EditorMode`)가 지도 클릭의 의미를 결정하며, 기본은 선택이다.

| 도구   | 값         | 역할                         | 하위 옵션                  |
| ------ | ---------- | ---------------------------- | -------------------------- |
| 선택   | `select`   | 도형 선택 · 이동 · 정점 편집 | 없음(기본)                 |
| 그리기 | `draw`     | 새 피처 추가                 | 폴리곤 / 패스 / 마커       |
| 경계   | `boundary` | 경계를 선택해 생성·병합      | 행정동 / 법정동 / 우편번호 |
| 반경   | `radius`   | 마커 기준 원형 커팅          | 반경 값                    |

- 도구는 sticky다(동작 후 자동 복귀 없음). 기본 도구는 선택.
- 클릭의 의미는 활성 도구가 결정한다. 무모드 추론은 쓰지 않는다(행정동/법정동 경계가 화면을 가득 채우면 "여백 클릭 = 그리기" 같은 추론이 성립하지 않음).

## 2. 기반 인터랙션 (도구와 무관, 항상 존재)

- **선택**: 도형 클릭 → 강조 + 패널 반영 + 편집 가능 판정. 더하기/빼기/반경 같은 모든 연산의 대상이 된다.
- **도형 이동**: 선택 모드에서 일반 드래그는 지도를 이동한다. 선택된 편집 가능 도형의 몸통을 `Cmd(macOS)/Ctrl(기타)+좌클릭 드래그`할 때만 도형을 이동하며, 다중 선택은 편집 가능한 도형을 함께 움직인다. 한 번의 드래그는 undo 한 단계로 커밋한다.
- **정점 편집**: editable 도형을 더블클릭하면 편집 상태로 진입한다(폴리곤/패스는 꼭짓점 드래그·우클릭 삭제, 마커는 점 드래그). ESC/완료 시 선택으로 복귀.
- **배타적 상태기계(계획)**: `interaction: idle | drawing | editing` — 한 번에 하나만. 그리는 중에는 다른 도형 선택을 잠그고, ESC로 진행 중 동작을 취소한다. (구현은 #9 · #11)

## 3. "그리기 = 추가" 개념

그리기는 "새 피처를 추가"하는 도구로 본다. 폴리곤/패스/마커는 "무엇을 추가할지"의 선택이다.

- 폴리곤 = 닫힌 면, 패스 = 열린 선, 마커 = 점 한 개.
- 도형마다 인터랙션이 다르지만(다중 클릭 vs 원클릭) "추가"라는 개념으로 묶이므로 한 도구의 하위 옵션으로 둔다.
- OpenLayers `Draw`는 생성 시점에 타입(Polygon/LineString/Point)을 정해야 하므로, 도형은 그리기 전에 미리 고른다.
- 생성된 피처의 lifecycle은 `Created`.
- **마커**는 한 번 클릭하면 즉시 완성한다.
- **패스**는 정점을 여러 개 찍고 지도 하단의 `패스 완료` 버튼 또는 `Enter`로 완성한다. 더블클릭으로는 끝나지 않는다.
- **폴리곤**은 서로 다른 정점 3개 이상을 찍은 뒤 시작점을 다시 클릭해야 완성한다. 마지막 정점 재클릭은 완료로 보지 않는다.
- 그리는 중 `Cmd/Ctrl+Z`와 redo는 정점 단위 로컬 history를 사용한다. 완성 시에만 scene에 새 레이어를 추가하고 전역 history 한 단계로 커밋한다.
- `ESC`는 취소 확인 모달을 연다. `그리기 취소`를 선택하면 진행 중 sketch만 버리고 scene과 전역 history는 변경하지 않는다.

## 4. 경계

- 경계는 **외부 카탈로그**다 — 질의해서 골라 쓰는 대용량 데이터셋이며 **레이어 패널에는 쌓이지 않는다**(수백~수천 개라 스택 레이어로 두지 않는다). 하위 옵션의 종류·라벨·순서는 `region_kind` 카탈로그가 단일 출처다. `regions_by_view`는 현재 줌에 맞춰 시군구 ↔ 상세 경계를 자동 전환하고, 클라이언트는 `truncated`를 줌인 안내로 표시한다.
- 경계는 "레이어"가 아니므로 readonly/이동 같은 레이어 상태를 따지지 않는다 — **복사해서 더하는 소스**로만 본다.
- 경계 클릭 시 동작(계획, #13). 데이터셋 선택(팝업)과 아래 동작은 분리한다:
  - **생성**: 고른 경계를 **새 편집 폴리곤으로 실체화(복사)** 한다 — 그때 비로소 스택 레이어(편집)가 된다. 카탈로그 원본은 보존.
  - **더하기(union)** / **빼기(difference)**: 선택된 폴리곤(target)이 있을 때만 활성. 경계는 readonly 카탈로그이므로 **항상 복사 병합**(원본 보존) — 같은 경계를 다른 도형에도 다시 더할 수 있다. 실제 불리언 연산은 §8 "병합/제거 모델"의 폴리곤 흐름이 담당한다.

## 5. 마커 & 반경

- **마커 = 1급 Point 피처**: 씬에 저장되고 host로 전달된다. 그리기-마커로 추가한다. (#41)
- OpenLayers adapter와 입력 스키마는 Point/Path를 포함한 GeoJSON geometry를 변환·렌더링한다.
- **반경**: 선택 폴리곤 + 선택 마커(기준점) 기준으로 원형 커팅한다. 폴리곤과 마커가 겹치지 않으면 무효. 원 안쪽 유지(clip)와 바깥 제거(difference) 중 어느 의미인지는 미정. (#40)

## 6. UI 패턴

- **하위 옵션 팝업 `ToolOptionPopup`**: 도구 버튼 옆(우측)에 붙는 작은 플라이아웃. 제목 + 닫기(X) + 옵션 목록으로 구성한다. 선택해도 닫지 않고 닫기 버튼이나 바깥 클릭으로 닫는다. 경계·그리기가 공용으로 사용하며, 레이어 패널 위(z-50)에 뜬다.
- **선택 인디케이터 `MovingHighlight`**: 선택된 항목 위치로 부드럽게 이동하는 범용 인디케이터. 항목의 실제 위치/크기를 측정하므로 가로·세로 배치 어디서나 동작한다. rail과 옵션 팝업에 함께 쓴다.
- **라벨 규칙**: 하위 옵션이 있는 도구 버튼은 "선택된 옵션 + 도구 의미"를 함께 표시한다. 예) `폴리곤` + `그리기`, `행정동` + `경계`. 처음부터 어떤 도구인지 알 수 있게 모호함을 줄인다.

## 7. 상태 매핑 (store)

- `activeMode`: `select`(기본) / `draw` / `boundary` / `radius`
- `activeDrawShape`: 폴리곤(기본) / 패스 / 마커 — `GeometryKind`의 부분집합 `DrawShape`
- `activeBoundaryKind`: `region_kind.kind` 문자열 또는 `null`(표시 끔). 기본은 `adminDong`이며, enum으로 고정하지 않는다.
- `selectedFeatureIds`, `hoveredFeatureId`, `activeLayerId`, `dirty`
- (계획) `interaction`, `editingFeatureId`
- 진행 중 Draw sketch와 정점 undo/redo는 adapter 로컬 상태로 관리한다. 완성 geometry만 store에 커밋한다.
- 원칙: OpenLayers 객체는 store에 넣지 않는다(adapter의 ref/cache로 관리).

## 8. 병합/제거 모델 (도형 불리언)

선택한 폴리곤(**target**)에 다른 폴리곤(**operand**)을 더하거나(union) 겹친 부분을 뺀다(difference). 모든 연산의 target은 "편집 가능한 선택 폴리곤"이고, operand는 합칠/뺄 상대다. 도구 용어는 **병합/제거**로 둔다.

### 현재 구현 (Select 모드, PR #74)

- 폴리곤 하나 선택 → **다른 편집 가능 폴리곤마다 도형 내부에 칩**(이름 + `+`/`-`)이 뜬다. 겹치는 폴리곤에만 `-`가 함께 뜬다. 칩을 클릭하면 그 폴리곤과 즉시 연산한다(픽 모드 없음).
- `+`(병합) = union, `-`(제거) = 겹친 부분 difference. **한 연산 = 1 undo**. 칩 위치는 OL `getInteriorPoint`로 도형 내부에 두고, 그 도형의 OL 이름 라벨은 칩이 대신 보여주므로 가린다.

### 레이어 상태 3분류

1. **편집**: 이동·정점편집·병합 가능 (target/operand 모두 가능)
2. **참고(readonly)**: 사용자가 배경으로 둔 잠긴 레이어. 이동 불가지만 병합 소스로 쓸 수 있어야 한다(향후)
3. **경계(외부 카탈로그)**: §4. 패널에 없음. 복사 병합 소스 전용

현재 입력/모델은 per-feature `locked?` + `visible?`만 받아 (1)·(2)를 **이진(locked/unlocked)** 으로만 표현한다. (3), "참고를 operand로 허용", 능력 분해(`canBeTarget`=편집 / `canBeOperand`=보임 / `movable` / 흡수 vs 복사)는 **향후 정비** 대상이다.

### 병합 정의 (C — 삭제 가능성 기준, 방향만 확정)

- operand가 **삭제 가능한 편집 peer** → **흡수 병합**: target에 union 후 소스 삭제 (= "둘이 하나"). **현재 구현**.
- operand가 **외부 경계 카탈로그** → **복사해 더하기**: target에 union 후 소스 보존. 표시용 단순화 geometry는 연산에 쓰지 않고, row id로 다시 받은 원본 geometry를 쓴다. **현재 구현**.
- 빼기 cutter는 모양만 제공하므로 **항상 보존**.
- 같은 `+`가 맥락에 따라 소스를 삭제(흡수)/보존(복사)하므로, 결과를 **툴팁·실행 후 토스트·역할 배지**로 명시한다(향후). 편집 소스에 한해 "원본 유지하고 더하기"를 보조 동작으로 제공할 수 있다.
