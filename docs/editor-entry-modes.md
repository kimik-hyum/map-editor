# 새 창 연동과 단독 실행 검토

상태: **설명·설계 검토만 반영. 에디터 실행 동작은 변경하지 않음.**

## 확인한 현재 동작

지도 렌더링과 도형 편집 자체에 부모 창이 필수인 것은 아닙니다. 현재 앱의 시작과 완료 계약이 새 창 연동에 연결되어 있습니다.

| 위치                                                                                                | 현재 역할                                                           | 단독 실행 시 분리할 책임                            |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------- |
| [editorStore.ts](../src/pages/editor/state/editorStore.ts)                                          | scene·sessionId가 null로 시작. 유효한 INIT으로 scene·history 초기화 | 외부 메시지와 독립적으로 새 scene을 시작하는 진입점 |
| [useEditorMessaging.ts](../src/pages/editor/messaging/useEditorMessaging.ts)                        | opener가 있을 때만 수신기를 등록. 첫 유효 INIT의 창·origin을 고정   | 새 창 통신을 담당하는 연동 어댑터                   |
| [EditorPage.tsx](../src/pages/editor/EditorPage.tsx)                                                | scene이 없으면 대기 안내. 준비되면 레이어 패널 표시                 | 현재 실행 모드에 맞는 시작 UI                       |
| [useEditorSessionActions.ts](../src/pages/editor/features/session/hooks/useEditorSessionActions.ts) | scene·sessionId 및 진행 중 도구·validation으로 완료 가능 여부 판단  | 공통 완료 조건과 결과 처리 방식 분리                |
| [useEditorMessaging.ts](../src/pages/editor/messaging/useEditorMessaging.ts)                        | SUBMIT/CANCEL은 연결된 열린 창이 있어야 성공                        | 결과 전송 또는 내보내기를 모드에 따라 선택          |

`{ version: 2, features: [] }` INIT도 유효합니다. 따라서 이미 그려진 폴리곤이 반드시 있어야 하는 것은 아닙니다. 현재 필요한 것은 ‘이 회차의 입력과 결과를 받을 창’입니다. JSON 파일을 읽고 내보내는 기능은 현재 단독 실행 경로로 구현되어 있지 않습니다.

## 제안하는 두 실행 모드

|             | 연동 모드                                                           | 단독 모드 — 미구현                          |
| ----------- | ------------------------------------------------------------------- | ------------------------------------------- |
| 시작        | 서비스가 연 팝업 → READY → INIT                                     | ‘새 지도’ 또는 JSON 가져오기                |
| 편집 데이터 | 서비스가 보낸 v2 scene                                              | 빈 v2 scene 또는 가져온 파일                |
| 완료        | 검증한 scene을 서비스에 SUBMIT                                      | v2 JSON 내보내기; 필요하면 별도 저장 어댑터 |
| 취소        | CANCEL을 보내고 서비스가 창 정리                                    | 변경 취소·새 작업 여부를 로컬에서 처리      |
| 접근 검증   | source·origin·sessionId 유지                                        | 파일 검증. 외부 메시지는 수신하지 않음      |
| 공통        | geometry 검증·도구·undo/redo·dirty 상태·참고 경계와 편집 scene 분리 | 동일                                        |

시작 데이터 공급과 결과 저장을 편집 도메인 밖의 세션 어댑터로 분리하는 방향이 적절합니다. 이 세션 어댑터는 **경계 데이터를 조회하는 어댑터와 다른 책임**입니다. 경계 인증은 Google·자체 인증·공개 접근 중 운영자가 선택하는 기존 정책을 유지합니다.

단독 모드가 추가되면 ‘저장’이라는 표현도 결과에 맞게 ‘JSON 내보내기’ 등으로 구체화합니다. v2 scene JSON과 GeoJSON FeatureCollection은 같은 파일 형식이 아니므로 가져오기·내보내기 지원 범위를 명시해야 합니다. 새로고침 복구·임시 저장 여부도 따로 결정합니다.

## 대기 조건만 제거하면 생기는 문제

- scene만 자동 생성하면 기존 완료 경로는 여전히 연결된 부모 창을 요구해 저장에 실패합니다.
- 타이머로 빈 scene을 만들고 나중에 INIT을 받으면 먼저 그린 도형과 히스토리가 초기화될 수 있습니다.
- opener가 없다는 이유만으로 모드를 추론하면 팝업 연결이 끊어진 서비스 연동을 단독 실행으로 오인할 수 있습니다.

따라서 명시적인 단독 시작 또는 모드 선택을 권장합니다. 연동 모드에서 INIT을 기다리는 상태는 유지하고, 타임아웃은 ‘입력 전달을 확인하세요’라는 안내에 사용합니다. 단독 편집을 시작한 뒤에는 외부 INIT으로 작업을 덮어쓰지 않습니다. 잘못된 INIT도 빈 편집으로 조용히 전환하지 않습니다.

## iframe과 문서용 화면 안내

현재 [public/\_headers](../public/_headers)의 `X-Frame-Options: DENY`가 운영 배포의 프레임 삽입을 차단합니다. 또한 메시징은 `window.parent`가 아닌 `window.opener`를 사용하므로, 헤더 하나만 바꿔도 iframe 연동이 완성되지는 않습니다.

이번 문서에는 실제 편집 화면 캡처와 HTML 강조 영역을 사용합니다. 도구 버튼을 누르면 위치와 설명이 바뀌고, 실제 편집은 정상적인 새 창 연동 예제로 체험합니다. 배포 보안 헤더와 editor 페이지는 유지합니다.

향후 iframe 안내가 필요하면 신뢰하는 문서 origin의 프레임 허용, 부모 메시지 검증, 모드·초기 데이터, 포커스·단축키, 종료 결과 처리까지 독립적으로 설계해야 합니다. 문서 설명을 위해 모든 사이트의 iframe 삽입을 허용할 필요는 없습니다.

## 이번 문서 반영

- `/`와 `/integration`에서 경복궁 사각형을 새 창으로 보내고, 저장 결과를 지도·JSON으로 확인합니다.
- `/editing`은 실제 화면 위에 선택·그리기·경계·반경·레이어·완료 위치를 강조합니다.
- 기존 대기 화면·INIT 검증·저장/취소·iframe 차단은 변경하지 않습니다.
