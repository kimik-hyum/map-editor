# 운영·변경 전 점검

과거 설계 질문의 답을 반복하기보다 변경 시 확인할 경계를 정리합니다. 지원 범위는 [별도 문서](editor-mvp-roadmap.md)를 기준으로 합니다.

## 변경에 맞는 검증

| 변경 대상        | 반드시 확인할 내용                                                     |
| ---------------- | ---------------------------------------------------------------------- |
| 부모 연동·schema | source/origin/session 검증, 중복 ID·좌표 오류, SUBMIT 재INIT 가능 여부 |
| 인증·callback    | 비로그인 편집, 팝업 성공·취소·실패, 로그인 전 scene·부모 연결 유지     |
| 도구·비동기 연산 | 새 INIT·로그아웃 후 늦은 응답 폐기, 한 동작당 undo 한 단계             |
| 문서·라우트      | 코드 예제 타입 검사, 목차 링크, 직접 URL 진입, 사전 렌더링 asset 경로  |
| 정적 배포        | 환경 변수 재빌드, auth/callback shell, 비밀 키 미포함                  |
| 경계 데이터      | 원천 기준일과 적재일 구분, current 스왑, 건수·좌표계·유효성 기록       |

기본 검증은 `npm run verify`, `npm run test:e2e`, `npm run build && npm run test:build`입니다. 모의 API E2E는 실제 Google Provider·배포 origin 설정 확인을 대신하지 않습니다.

## 데이터와 권한

- scene은 부모가 제공하는 편집 초안입니다. 최종 저장 권한은 부모 서버가 검사합니다.
- locked·visible은 UI 상태입니다. 변경 불가능한 서버 권한이나 민감 데이터 격리를 표현하지 않습니다.
- 에디터의 Google 세션과 부모 로그인은 별개입니다. 토큰은 부모 메시지에 포함하지 않습니다.
- 프런트엔드 origin 허용 목록, 함수 origin 목록, OAuth callback 목록은 각각 관리합니다.
- 서버 계정 제한이 없으면 모든 유효한 Google 사용자를 허용합니다. CORS를 curl 차단으로 설명하지 않습니다.

## 성능을 바꿀 때

예상 상한의 도형·정점 수로 INIT, 정점 편집, 다중 선택과 팬·줌을 먼저 측정합니다. 병목이 확인된 경로에만 diff sync나 캐시를 적용합니다. 원격 경계 전체를 편집 scene에 넣지 않습니다.

## 원천 데이터 날짜를 표시할 때

DB의 base_date가 공식 기준일이라는 가정을 하지 않습니다. 원천 배포 문서·다운로드 기록·적재 프로필을 함께 확인합니다. 현재 버전 모델과 2026-09-06 점검의 날짜 한계는 [경계 API 문서](supabase-region-api.md#데이터-버전과-운영-점검)를 참고하세요.
